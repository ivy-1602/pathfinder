# Maarg: A clearer direction for every student.

A Flask web app that recommends electives, courses, certifications, hackathons, internships-prep and scholarships to students, explains every recommendation, and includes a local advisor, fit analysis and week-by-week roadmaps.

## What's new compared with the starter

| Area | Starter | Now |
|---|---|---|
| Accounts | Anonymous profiles | Sign-up and login (hashed passwords), CSRF protection, edit profile |
| Matching | Keyword overlap | TF-IDF text similarity (scikit-learn) plus interest, skill, goal and level signals, and a small peer signal from same-branch students |
| Eligibility | Filter | Filter, plus a "Within reach" list showing what's missing (CGPA, semester, branch) |
| Catalogue | 6 items | 30 items across 10 categories, with level, mode, cost, duration and optional deadlines |
| Explore | none | Search and filter by category, level, cost, mode and eligibility |
| Tracking | none | Save, start, complete or hide ("Not for me"); hidden and completed items leave your recommendations |
| Skill gaps | none | "You'd build" per item and a dashboard strip of the skills that unlock the most matches |
| Assistant | none | Offline advisor chat, per-item fit analysis and roadmap that links only to catalogue items |
| Admin | none | Add or delete opportunities (with deadlines) and view students |
| API | none | `GET /api/recommendations` returns scores, components and reasons as JSON |

## Run locally (Windows PowerShell)

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
copy .env.example .env     # then edit .env
python app.py
```

If activation is blocked, use `.\.venv\Scripts\python.exe` instead of `python`. Open http://127.0.0.1:5000.

**Fresh database:** the app now uses `instance/pathfinder.db`. Your old `students.db` is left untouched and unused.

## No external APIs

Nothing leaves your computer. Matching uses a pure-Python TF-IDF implementation locally; the advisor, fit analysis and roadmap are generated by the local `assistant.py`. No keys or accounts needed.

## Becoming an admin

Put your email in `ADMIN_EMAILS` in `.env`, register with that email, and an Admin link appears.

## How the score works (0-100)

- 35% topic similarity (TF-IDF on your interests, skills and goal against each item's title, description and tags)
- 20% interest overlap, 15% skills you already have, 20% career-goal alignment, 10% level fit for your semester
- Up to +5 if other students in your branch saved it

Shorthand like ML, NLP, DSA and UI/UX is normalised before matching. Open any opportunity to see the breakdown.

## Honest limits

- The catalogue points to real public platforms, but the entries are resources to explore, not confirmed vacancies. CGPA and semester limits on seeded items are illustrative. Add real, dated opportunities in Admin.
- Scores are heuristics, not predictions. Verify requirements with each provider.
- Before a public deployment: use a production server (gunicorn or waitress), HTTPS, a real database such as PostgreSQL with migrations, login rate limiting and password reset, and set `SECRET_KEY`.

## Deploy on Vercel

1. Create a free Postgres database (Neon, Supabase, or Vercel's Marketplace) and copy its connection string.
2. Push this folder to GitHub and import the repo in Vercel (Framework: Flask is detected automatically).
3. In Project Settings > Environment Variables add `DATABASE_URL`, `SECRET_KEY` (a long random string) and `ADMIN_EMAILS`.
4. Deploy. Tables and the starter catalogue are created on the first request.

Vercel's filesystem is read-only, so SQLite cannot be used there. Static files must live in `public/` (already set up).
